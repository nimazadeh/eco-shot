## 0. Install and activation status (with evidence)

| Question | Answer | Evidence |
|---|---|---|
| Are the skill files present locally and unmodified? | **Yes**: vendored under `skills/vendor/<owner>-<repo>/`, byte-for-byte, `modified: false` for every source | `vendor/SOURCES.lock.json`; `cd skills/vendor && sha256sum -c CHECKSUMS.sha256` |
| Can this agent runtime activate skills natively (skill loader, `.claude/skills`, `.agents/skills`, plugin install)? | **No** | Phase 0 inspection: no skill-loader tool in the tool list, no `.claude/` or `.agents/` discovery directory, no agent env vars. | How is a skill "activated" here? | **Pointer-based, read-at-use**: open the skill's `SKILL.md` (and only the reference files the task needs), follow its procedure, and log it in `report.md` | `SKILL_USAGE_MAP.md` section 1 |
| Was any skill script executed in Phase 0? | **No** (only static reading and file integrity checks). Impeccable's engine launcher was deliberately not run (it downloads a native binary) | Phase 0 command log in `report.md` |

Legend. **Mode**: *user-invoked* = `disable-model-invocation: true` (the human types it; here: run only when the owner's phase plan or request calls for it and announce it); *model-invoked* = the agent may reach for it. **Read in Phase 0** states exactly what was read in this session (`full`, `partial`, `inventory only`, `not read`); anything not read in full must be read before first use. **Project use**: `core` = planned in the phase plan, `on-demand`, `candidate` (decision pending), `reference`, `n/a`.

## 8. Known gaps and exact blockers (nothing here was silently skipped)

1. **No native activation** in Arena Agent Mode (section 0). Mitigation: pointer-based activation via `SKILL_USAGE_MAP.md`; the owner can additionally install the upstream plugins on their own machine (`claude plugin install mattpocock-skills@claude-plugins-official`, `npx skills add <repo>`), which would then read from their own skill directories, not from `skills/vendor/`.
2. **No sub-agent tool.** Skills that mandate sub-agents (Matt `code-review`, `implement-spec`, `research`, `improve-codebase-architecture`; Addy `/ship` fan-out; Impeccable `critique`, finish reviewer, documenter) run sequentially/inline with the disclosures their own text requires.
3. **`browser-testing-with-devtools`** needs the `chrome-devtools` MCP server (not available here) and has no scripts; fallback evidence route = Playwright (`webapp-testing`) + Lighthouse CLI, both unverified in this sandbox until Phase 4 installs them.
4. **Impeccable engine binary not fetched or run.** Skill features that call `impeccable <verb>` (context, detect, critique-storage, live, build-phase, concept-seed, hooks, doctor) are unavailable until the owner approves a first run.
5. **Partial reads.** Not read in full in Phase 0: Matt `.agents/writing-docs.md` (maintainer-only) and `docs/`; Addy's 18 non-required skills, `references/{performance,observability}-checklist.md`, `references/orchestration-patterns.md`, `agents/web-performance-auditor.md`; web-quality `references/{A11Y-PATTERNS,WCAG,SECURITY,LCP,INP,CLS,RUM}.md`; Vercel `rules/*.md` (the compiled guide that contains all 70 + 8 rules *was* read); Impeccable references marked "not read" in section 6, the truncated middle of `new-work.md` and `layout.md`. Each must be read in full at first use and logged.
6. **Vercel upstream has no LICENSE file** (MIT declared in README and frontmatter only).
7. **Windows (owner OS).** Bash-only helpers: Matt `diagnosing-bugs/scripts/hitl-loop.template.sh`, `wizard/template.sh`, `git-guardrails-claude-code` script; web-quality `analyze.sh` (needs `jq`). Use Git Bash or WSL. Python helper `with_server.py` works but `terminate()` may leave child Node processes on Windows.
8. **Sandbox tooling gaps for later phases:** pnpm, yarn, bun, psql, docker, gh are not installed here (Node 20.20.2, npm 10.8.2, git 2.47.3, Python 3.13 are).
